# 🚑 救途 RescueRoute｜救護送醫導航

> 第一次，就送對醫院。　板橋救護義消 尤崧保／新板警消 尤偉檁 共同製作
> 更新資料：115年度第三季新北市各急救責任醫院急重症病人24小時專科處置能力一覽表

救護人員在現場貼上（或說出）勤務中心的案件摘要，系統自動辨識病患**性別、年齡、主訴、發作時間**，依距離／車程列出鄰近醫院，結合**醫院能力表、服務時段**與**治療時間窗**，標示「符合病患需求、此刻能做、到院時還來得及」的醫院；還能一鍵送出**到院前通知**（附 ISBAR 交班摘要），醫院端即時回覆「可收治／請改送」，並在來院看板上看到救護車位置與倒數。

## 設計緣由

救護人員出勤時，從火場救出一名患者，口鼻有碳粒、吸入濃煙。處置後送往市立三重醫院，到院後檢查發現一氧化碳濃度過高、喉頭水腫，需要高壓氧治療，只能立即再轉送到有能力處置的醫院。

這個 App 的目的，是在救護人員判斷患者可能的病因後，**直接選出有能力處置、距離近、此刻能收治的醫院**。現場分秒必爭，所以 App 必須**越方便、越快速、越準確越好**。

> 以本系統的醫院資料估算，這個案例若直送有高壓氧的重度級醫院，約可省下 48 分鐘（市區平均車速、轉院準備 45 分鐘；實際依路況而定）。

## 大量傷病患分流的演算法

1. 每間醫院的可收治人數：有醫院回報就用「急救室床數 − 使用中」；沒有就依等級估計（重度級：紅 3、黃 6、綠 10）。急診通報滿載、ICU 沒空床時會下修
2. 依危急程度（紅 → 黃 → 綠）逐一指派給「成本」最低的醫院：**成本 = 車程 ＋ 該院已分配人數 × 5 分 ＋（沒有所需專科能力時 ＋20 分）**
3. 限制：紅色傷患需中度級以上；創傷事故的紅色傷患需重度級＋創傷團隊；60 分鐘車程外不分配
4. 「已分配人數 × 5 分」讓傷患自然分散，避免全部送進同一間醫院，結果會和「全部送最近醫院」對照

## 功能

**後送建議**（預設分頁）
- **案件摘要自動辨識**：貼上派遣內容（例：`急病 一名男性年約35歲 主訴內科OHCA`）
  - 關鍵字辨識立即出結果；設定 Gemini 金鑰後，AI 再補強：區分內科／外傷 OHCA、嚴重度、判斷理由、**建議需要的處置能力**
  - 摘要內容更新時欄位即時跟著變；手動改過的欄位（✎）不會被蓋掉
  - 主訴可設定「辨識優先度」，例如同時提到車禍與 OHCA 時以 OHCA 為主
- **依病患條件**：22 種主訴，依性別／年齡／主訴對應醫院需求（後台可調整）
- **依處置能力**：8 大類、29 項能力可複選
- **兩種排序**
  - 建議順序：適合且可收治 → 適合但壅塞／滿載（建議先電話確認）→ 其他醫院，同組再依距離
  - 距離順序：單純由近到遠
- **醫院清單**：「醫院名稱（等級）」＋「特殊處置：高壓氧、心導管…」，右側為車程分鐘與公里數；有醫院回報時顯示急救室、候診、候床、ICU 空床。忙碌中的設備會顯示「高壓氧（忙至 14:25）」；非服務時段的能力會劃掉並寫出時段，且不會被算成適合
- **點一下醫院 → 開啟 Google 地圖**（iPhone 有裝 App 會直接開 App，可看醫院資訊、按路線）
- 前 N 間都不適合時，補上最近一間適合的醫院
- **地圖模式**、撥打電話
- **外觀**：日間（白色車身配紅黃反光條紋）／夜間（深墨藍），預設跟隨手機設定，可在本機設定切換

## 架設教學（從零開始）

需要架設的只有 **1. GitHub Pages（必要）**；**2. Gemini（選用）**、**3. Firebase（選用，全隊共用時才需要）**。車程（OSRM）、地圖（CARTO）是公開服務，不用申請。

### 1. GitHub Pages：把 App 放到網路上（免費，約 15 分鐘）

1. 到 [github.com](https://github.com) 註冊帳號（記住帳號名稱，網址會用到）
2. 右上角「＋」→ **New repository** → 名稱填 `rescueroute` → 選 **Public** → Create repository
3. 在新的 repository 頁面按 **uploading an existing file**，把這 8 個檔案拖進去（全部放在最外層，不要放資料夾）：
   `index.html`、`sw.js`、`manifest.webmanifest`、`firestore.rules`、`README.md`、`icon-192.png`、`icon-512.png`、`apple-touch-icon.png` → 按 **Commit changes**
4. **Settings → Pages** → Source 選 **Deploy from a branch**，Branch 選 `main`、`/ (root)` → **Save**
5. 等 1～2 分鐘，網址是 `https://你的帳號.github.io/rescueroute/`
6. iPhone 用 Safari 開這個網址 →「分享」→「加入主畫面」，就會像 App 一樣有圖示

> 之後要更新：在 repository 按 **Add file → Upload files**，上傳新檔案覆蓋即可。手機若還是舊版，把 App 關掉重開一次（離線快取會自動換新）。
> ⚠️ 定位必須在 https 網址才能用，GitHub Pages 預設就是 https。

到這裡就是**示範模式**：所有功能都能用，資料存在每台手機自己的瀏覽器；「通知醫院」只在同一台裝置示範。

### 2. Gemini AI（選用，讓主訴辨識更聰明）

1. 到 [Google AI Studio](https://aistudio.google.com/apikey) 用 Google 帳號登入 →「建立 API 金鑰」→ 複製
2. App 選單 →「本機設定」→ 貼上金鑰 →「測試連線」→ 儲存
3. 每台手機要各自輸入一次

> 🔒 金鑰**不要**寫進 `index.html` 或上傳 GitHub（公開會被盜用）。案件摘要會傳給 Google 分析，請勿輸入姓名、身分證字號等個資。

### 3. Firebase（選用：全隊共用資料、醫院端真的收得到通知）

1. [Firebase Console](https://console.firebase.google.com/) →「新增專案」（可以不開 Google Analytics）
2. 左側 **Firestore Database** →「建立資料庫」→ 位置選 `asia-east1`（台灣）→ 先選「正式版模式」
3. 左側 **Authentication** →「開始使用」→ 登入方式啟用「**電子郵件/密碼**」和「**匿名**」→ 到「Users」新增管理者帳號（你的 Email＋密碼），醫院人員帳號也在這裡新增
4. **Firestore → 規則**：把 `firestore.rules` 的內容整份貼上，把 `your-admin@example.com` 改成管理者 Email →「發布」
5. 齒輪 **專案設定 →「你的應用程式」→ 網頁（</>）** → 隨便取名 → 複製畫面上的 `firebaseConfig`（apiKey、authDomain…）貼進 `index.html` 最上方的 `FIREBASE_CONFIG`（這組 apiKey 可以公開，安全性由規則控制）
6. **Authentication → 設定 → 授權網域** → 新增 `你的帳號.github.io`
7. 把改好的 `index.html` 重新上傳到 GitHub
8. 打開 App → 管理後台登入 →「設定／資料」→「寫入預設測試資料」（會寫入 19 間醫院與能力表）
9. 後台「醫院帳號」：把醫院人員 Email 綁定到醫院，他們用醫院端登入就能回報量能、回覆到院前通知

權限：救護員不用登入即可查詢；只有管理者能改醫院資料；醫院帳號只能回報、回覆自己醫院；到院前通知只有送出的救護車、該醫院、管理者看得到。

## 報告可以探討的議題

- **醫院回報意願**：醫院為什麼要花人力即時回報？誘因怎麼設計（例如列入評鑑）？能否直接和醫院資訊系統（HIS）或衛福部急診即時資訊串接，免人工輸入？
- **避免把醫學中心塞爆**：如果大家都照「適合」送重度級醫院，會不會造成新的壅塞？大量傷病患分流用「已分配人數」做懲罰，就是一種解法
- **時間窗的取捨**：中風就近溶栓或直送取栓、STEMI 是否先到非 PCI 醫院打溶栓，都沒有標準答案，取決於距離與當地醫療網
- **和現有制度的關係**：與 119 派遣、緊急醫療應變中心（EMOC）、衛福部急診即時資訊怎麼整合，而不是另起爐灶
- **AI 的責任與限制**：AI 判讀錯誤時誰負責？為什麼本系統讓 AI 只做「建議」、最後由救護員確認
- **個資與資安**：派遣內容送給 Gemini 分析的隱私問題；為什麼紀錄只保存主訴分類與時間，不存病患姓名
- **資料正確性**：醫院能力標籤誰負責維護、多久更新一次

## 資料來源與限制

- 醫院能力：115年度第三季新北市各急救責任醫院急重症病人24小時專科處置能力一覽表（19 間）；林口長庚不在此表，依管理者設定為全部具備
- 地址、電話：衛福部醫院名冊；**座標為概略值**，正式使用前建議逐一確認
- 服務時段由能力表文字整理（例如「平日上班時間」＝一至五 08:00-17:00、「門診時段」＝一至五 08:00-17:00、六 08:00-12:00），實際以醫院公告為準
- 衛福部／健保署的急診即時資訊沒有公開 API（各醫院格式不一），目前拿不到醫院即時滿床資訊，因此 App 不顯示即時量能（送醫前請電話確認）
- 車程使用 OSRM 公開路線服務（一般車速估算，不含救護車優先通行），無法連線時改用直線距離
- 本工具僅輔助判斷，實際收治以醫院／勤務中心為準
